# Starter issues for the public launch

Create these issues after the public repository is live. Assign each to `@maintainers` until a contributor volunteers.

1. **Add keyboard focus tests for filters** — acceptance: Vitest coverage proves all filter controls have accessible labels.
2. **Document a repository-review rubric** — acceptance: contributor-facing rubric covers scope, sources, license, and maintenance.
3. **Add an “editorial updates” collection** — acceptance: visible collection with at least eight entries and rationale.
4. **Improve mobile filter ergonomics** — acceptance: filters remain usable at 320px width with no horizontal scrolling.
5. **Add a dedicated contributing screenshot** — acceptance: README shows the submission-to-publication flow.
6. **Audit all null licenses** — acceptance: each null license has a source or a documented reason it remains unknown.
7. **Add an accessibility smoke test** — acceptance: automated check covers home, explore, and a repository page.
8. **Add repository data-change tests** — acceptance: CI fails when canonical and scores are out of sync.
9. **Create an infrastructure collection** — acceptance: at least eight curated entries with an explanatory intro.
10. **Add a public freshness dashboard section** — acceptance: methodology reports last metadata and editorial verification dates.
